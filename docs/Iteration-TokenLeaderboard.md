# 代币榜单迭代

## 1. 变化内容

新增“代币榜单”模块，展示近期监控对象买入过的代币，并按时间窗口切换：

- `1d`
- `3d`
- `7d`
- `15d`

每个榜单项展示：

- 代币名称
- CA
- 市值
- 距离最近一次监控买入的变化百分比
- 购买该代币的监控人数
- 购买该代币的监控人名单

榜单支持按监控人数排序，默认按监控人数降序展示。

## 2. 现在推进的原因

现有 Dashboard 能展示最近交易明细，运营视角需要快速识别多名监控对象共同买入的代币。这个榜单把单笔信号聚合为“人群共识”视图，帮助判断后续跟踪优先级。

## 3. 目标用户

主要服务使用 Sol-Tracker 做链上监控的操作者。用户通过榜单快速发现多名重点监控对象同时关注的代币，并进入 DexScreener 或 Solscan 做后续判断。

## 4. 本轮范围

- 新增后端 API，按窗口聚合 `BUY` 类型日志。
- 聚合口径以 `people` 为单位，同一个人的多个地址买入同一代币只计为 1 人。
- 返回每个代币的名称、CA、市值、监控人数、监控人名单。
- 返回当前市值相对最近一次监控买入时市值的变化百分比。
- 新增 Dashboard 榜单组件。
- 提供 `1d / 3d / 7d / 15d` 时间窗口切换。
- 提供按监控人数排序能力。
- 保留移动端可读布局。

## 5. 本轮边界

- 卖出、净买入、持仓变化、买入金额排行进入后续迭代。
- 榜单数据使用已入库的 webhook 日志作为来源。
- 市值优先使用日志里的 `token_info.marketCap`，缺失时可复用现有 `resolveTokenInfo`。
- 人员名单以当前 `people.name` 为准，历史日志里的 `token_info.personName` 作为兜底。

## 6. 验收标准

- Dashboard 出现代币榜单模块。
- 切换 `1d / 3d / 7d / 15d` 后，榜单按对应时间窗口刷新。
- 仅统计 `BUY` 日志。
- 同一监控人的多个地址买入同一 CA 时，监控人数计为 1。
- 榜单项显示名称、CA、市值、监控人数、监控人名单。
- 榜单项显示距离最近一次监控买入的变化百分比。
- 默认排序为监控人数从高到低。
- 默认只展示 Top 50 且至少 2 个监控人买入的 token。
- API 对非法窗口返回清晰错误。
- 空数据时展示稳定的空状态。

## 7. 假设

- `logs.address` 能关联到 `addresses.address`，再关联到 `people.id/name`。
- `logs.token_info.mint` 是榜单 CA 的主来源。
- `logs.token_info.action` 或 `logs.type` 可识别买入行为。
- 当前数据量可以先用 API 层聚合；数据量增长后再下沉到 SQL view 或 materialized view。
